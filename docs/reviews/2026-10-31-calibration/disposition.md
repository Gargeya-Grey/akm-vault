## Finding dispositions

1. **P2-WARN-OWNERSHIP. Accepted, open, inspection-supported.** `Gate.warnings` is shared across locks/opens, and `warnings()` drains it for whichever session is active. A journal failure after A's commit can surface as a misleading warning in B. The old frontend stale-reply test does not cover native queue ownership. Start unit 1a with native and actual App/API red regressions for both ordinary completion and locking-overtaken completion. Bind operation-specific warnings to their origin while preserving a secret-free acknowledgment for unavailable A. Do not simply clear the queue and lose the outcome, or discard app-global clipboard/policy warnings indiscriminately.
2. **P2-JOURNAL-CLAIMS. Accepted, open, inspection-supported.** Missing logs can verify successfully, UI copy overstates completeness, some event labels turn pre-action records into completed events, and verify/read use separate locks. Unit 1a must specify explicit absent/corrupt/consistent-but-unauthenticated/incomplete-or-unknown states, attempt versus known outcome, and one locked displayed snapshot. Missing/deleted logs and failed disclosures must not imply that nothing happened.
3. **P2-JOURNAL-IDENTITY. Accepted as a design gate, not a failed future implementation.** Unit 1b cannot start storage migration until rename, clone, replacement, rollback, ambiguity and audit-without-password behavior are defined. A path, mutable content hash or copied root UUID is not automatically sufficient. Journal, mapping and lock need private local ACLs and a defined reparse/unsupported-storage policy. No silent old-vault mutation, merged clone history or synced-sidecar fallback is authorized.
4. **P2-JOURNAL-OUTCOMES. Accepted as a preservation/design gate.** Preserve damaged bytes and classify observable damage, not an unprovable cause such as "crash rather than tampering." Existing CLI tests deliberately fail closed on logging failure before reveal/export/launch. Keep that policy unless an explicit reviewed change replaces it. After commit or publication, preserve truthful non-retryable completion plus warning. These are different boundaries.
5. **P2-HISTORY-SEMANTICS. Accepted as concrete design/test requirements.** Native tracked APIs need no-op detection, same-second edit and clock-rollback policy, separate recycle/permanent-delete/restore semantics, parent/UUID preservation and tombstone timing. Test stale foreign copies in both merge directions with real KeePassXC and shared/history-only attachments. History design need not wait for journal storage completion; only stable outcome contracts and shared-file ownership are dependencies.

Correct backend arithmetic alone will not fix stale presentation.
