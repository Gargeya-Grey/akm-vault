**1. Ranked findings**

**U1-R1-01 · P2 · Extracted plaintext survives a vault revision change.**  
`desktop/src-tauri/src/session.rs:1176`, `desktop/src-tauri/src/session.rs:1233`.

`copy_stamped` discards the stamped revision; `reveal` checks only ticket and presentation. A same-session rotation, removal or reload between extraction and delivery therefore does not refuse the old plaintext.

**Reproduced:** using the production `Session` and core with fake data, extraction followed by rotation still revealed `"fake-old-value"`. Extraction followed by removal returned `Ok(())` from copying and placed the removed key’s value in the fake clipboard. This leaves the class sweep incomplete and violates contract 4’s suppression of obsolete plaintext.

**Closing test:** pause single-key and bulk disclosures after extraction, complete a same-session rotate/remove/reload, then resume delivery. Require refusal before page or clipboard publication, including when copying waits for its lease mutex.

**U1-R1-02 · P2 · A rejected clipboard completion does not revoke its publication.**  
`desktop/src-tauri/src/session.rs:1193`, `desktop/src-tauri/src/session.rs:555`.

If presentation expires during publication, the final check returns `viewChanged`. However, presentation expiry sets no `cleanup_owed`, and `settle_held(..., only_if_owed = true)` performs no cleanup. The obsolete publication remains.

**Reproduced:** the fake backend expired presentation after publication and before the final check. The reply was `viewChanged`; the fake clipboard still contained `"fake-first"`. Decision 3 describes check, act, check and cleanup, but this refusal does not perform that cleanup.

**Closing test:** expire presentation between publication and the final check through the command’s fake Win32 path. Require ownership-aware revocation, preserve a newer identical user copy, and report uncertainty if revocation fails.

**U1-R1-03 · P2 · The notification commit gates scheduling, not Windows delivery.**  
`desktop/src-tauri/src/reminders.rs:89`, `desktop/src-tauri/src/reminders.rs:248`.

The locked dependency is `tauri-plugin-notification` 2.8.0. Its Windows `show()` implementation (`tauri-plugin-notification-2.8.0/src/desktop.rs:435`) builds the notification, queues `notification.show()` on an asynchronous task, and returns. That later call carries no session check, and its error is discarded.

**Inspection:** session A can queue a notification, release the gate, lock or be replaced by B, and only then hand A’s notification to Windows. This is different from Windows displaying something it accepted before locking. `Delivery::Sent` also reports scheduling even when the subsequent Windows call fails. The synchronous fake-notifier test misses both cases.

**Closing test:** put a barrier immediately before the queued task’s actual Windows handover. Lock or open B, release it, and require no old-session handover. Separately fail that handover and verify truthful delivery state.

**U1-R1-04 · P2 · Panic handling can report a committed import as failed.**  
`desktop/src-tauri/src/commands.rs:1198`, `desktop/src-tauri/src/session.rs:1105`, `desktop/src-tauri/src/outcome.rs:69`.

Import ignores the outcome witness and learns completion only from the ordinary return. Unwinding after replacement bypasses `CommitLog::finish`; the outcome retains its default `Failed`.

**Reproduced with fault injection:** a real import into a fake vault committed, then an injected unwind passed through production `Session` and `Outcome`. The record was `importFailed`; reopening the vault confirmed the import was saved. No input-triggered production panic was established.

There are two related inspection failures:

- A panic under the commit gate poisons it. `record_operation` silently skips recording when obtaining that gate fails.
- After a terminal’s `done()`, the blocking wrapper can still return the retry-inviting `internal` error. The page treats that as a known error and acknowledges the surviving started record.

The disclosed limit in commit-point section 9.3 does not satisfy contracts 4 and 7. Decision 15 prevents panic-text leakage but can misstate completion.

**Closing test:** inject faults immediately after vault replacement and terminal resume through the generated handlers. Require one truthful outcome and a completion-safe reply. Include an unwind under the gate and the page’s acknowledgement path.

**U1-R1-05 · P2 · Settings preparation overwrites and deletes an unowned temporary file.**  
`desktop/src-tauri/src/settings.rs:142`, `desktop/src-tauri/src/settings.rs:177`.

Preparation uses the fixed name `settings.json.tmp` and truncating `fs::write`. Its destructor then deletes that pathname without establishing ownership. Another AKM instance’s preparation or an existing foreign file can be overwritten and deleted even when this opening never commits.

**Reproduced:** the unchanged preparation/destructor code overwrote a fake sentinel at that name, then deleted it on drop.

**Closing test:** preserve a pre-existing sentinel and interleave two independent preference stores. Use uniquely created, owned temporary files and ensure cancellation/publication touches only the owned object.

**U1-R1-06 · P3 · The structural commit-point guard accepts a straightforward bypass.**  
`desktop/src-tauri/src/session.rs:5193`.

An added helper can import `std::process::Command as Child`, check the session, and call `Child::new(...).spawn()` outside the gate. It contains none of the prohibited spellings and takes no `Held`.

**Reproduced:** adding that helper to the guard’s in-memory source inventory passed its existing assertions. The helper was never executed.

**Closing test:** retain this alias mutant and require rejection. Extend enforcement to resolved calls or restrict process creation through an interface that cannot be bypassed by renaming an import.

**U1-R1-07 · P3 · Accepted operation IDs do not round-trip exactly.**  
`desktop/src-tauri/src/outcome.rs:108`, `desktop/src-tauri/src/session.rs:1317`.

Dispatch accepts a valid uppercase UUID and normalizes it to lowercase. Acknowledgement compares strings exactly.

**Reproduced:** an accepted uppercase operation ID produced a differently spelled record ID; acknowledgement using the original ID left the record. The current page generates canonical UUIDs, so this is a limited wire-contract defect.

**Closing test:** test all accepted UUID representations through dispatch and acknowledgement. Preserve the supplied ID exactly, or reject noncanonical representations before dispatch.
