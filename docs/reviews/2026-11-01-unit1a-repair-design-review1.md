DESIGN: NO

1. **Blocking — §1.3 lock; §2.3 invariant 6.** The proposed table states that locking never waits for cleanup, but it does not specify how to achieve that. Today, `Session::lock` (`desktop/src-tauri/src/session.rs:222`) holds the session gate while `locked_gate` synchronously calls cleanup before retiring the owner. A cleanup already running from `tick` also holds that gate. A blocked clipboard operation can therefore delay locking or its notification. Specify a cleanup worker and generation-safe handling of late results. Add tests that hold cleanup blocked both when lock starts it and when a tick started it first; locking and its notification must complete before the block is released.

2. **Blocking — §1.3 Session paths; §2.3 transitions.** The inventory omits cleanup on `start_open` (`desktop/src-tauri/src/session.rs:314`), and `tick` calls `clear` while locked rather than only when a lease is due. If idle expiry occurs inside `gate()` (`desktop/src-tauri/src/session.rs:177`), a subsequent `lock()` or `tick()` can attempt cleanup a second time in the same call. The exit row also misses the close and exit handlers in `desktop/src-tauri/src/lib.rs:44`, which call `lock` before any `Drop`. Add these paths, pre-publication rejection paths, and their interactions to the state model. Test attempt counts, warning episodes, reopen, and shutdown through the actual callers.

3. **Blocking — §1.1 rollback; §2.1 `Residual`; §2.2 C5b.** The design recognizes that a failed `EmptyClipboard` has an unproven effect at exit 7, but does not apply that premise to failed rollback or failed cleanup. The sequence is sampled *before* rollback in `desktop/src-tauri/src/clipboard.rs:407`. If a failed empty changed the sequence while leaving secret data, the next cleanup would classify that change as `Replaced` and release the lease without warning, although no newer writer was observed. Either establish and document a narrower Windows failure guarantee, or model this as uncertainty. For publication, evidence can be assessed within the original open interval; for a later cleanup, do not adopt a later sequence in violation of contract 10. Add a fake failure with side effects and a subsequent newer identical copy.

4. **Blocking — §1.1 exit 7; §2.1 `Untouched`; §2.3 invariant 2.** `Untouched` says the clipboard was not emptied, while the same design says exit 7 cannot establish that. Keeping lease A in this case can also contradict "a failure after the clipboard was emptied never leaves an earlier lease." Represent the initial-empty result as uncertain and state the conservative lease policy without asserting an unobserved effect. Also, requiring a variant does not prevent a new post-empty exit from returning `Untouched`; bind outcome construction to the publication phase or otherwise enforce that distinction, and test both possible effects of the failed call.

5. **Blocking — §2.5 output intent; §3.2 disclosure test.** `Shown` has no protected payload or capability, and today's renderer receives the complete `ApiKey` (`crates/akm-cli/src/main.rs:690`). A new metadata field or alias could print `key.secret` while being classified as `Metadata`; the listed tests only exercise the existing `secret` spelling. Make the metadata renderer receive secret-free data, and require authorization before a disclosure-capable renderer or sink receives the secret. Add a caller-level mutant for a new secret alias or sink, as well as normalized existing field names.

6. **Blocking — §3.1 publisher table.** The specified `Session::copy` is a test-only adapter (`desktop/src-tauri/src/session.rs:587`) that passes no presentation stamp. Production key and environment copy commands (`desktop/src-tauri/src/commands.rs:324`) call `copy_stamped`, which supplies that stamp. The proposed table can therefore pass without exercising the production presentation checks. Drive the real fake-Win32 publisher through `copy_stamped`, and cover both production copy command paths and their journal behavior.

7. **Blocking — §3.1 "each step" and C1–C6.** Several stated combinations cannot be reached through that caller. Production passes `require_empty = false` (`desktop/src-tauri/src/clipboard.rs:649`), so row 6 belongs to the opt-in publisher path. C2 cannot arise from an ordinary Session lease after the zero-sequence handling in `ClipboardLease::clear` (`desktop/src-tauri/src/clipboard.rs:130`). The fake Win32 API also cannot fault row 3: encoding calls Windows directly (`desktop/src-tauri/src/clipboard.rs:266`). Separate unreachable production cases from direct publisher tests, and add an injectable conversion boundary for the reachable encoding-failure test.

8. **Blocking — §3.2 export test; §5 order and stop.** The design says the `run_with` test cannot run on today's code, then requires every §3 test to fail on today's code or the work to stop. Moreover, 1A-R8-04 is a **coverage** finding: the inspected export behavior may already be correct, so a truthful test need not fail on the affected version. Specify a behavior-preserving caller seam and use the warning/exit mutants to prove this coverage. Keep fail-before-fix regressions for actual defects, in line with `AGENTS.md:39`.

9. **Blocking — §1.4 clipboard texts; §2.4; §3.1 frontend test.** The proposed Settings lock sentence says AKM "tries" but does not say the copy may remain, as the recorded owner decision requires. The inventory also omits visible native errors such as owner creation, allocation, initial empty, publication, and NUL errors in `desktop/src-tauri/src/clipboard.rs:491`. Its README line 141 (`README.md:138`) concerns **file-export** cleanup, not clipboard cleanup. Complete the inventory, fix the lock text, and test literal rendered wording, including "may remain," rather than only comparing callers with their shared helper. Include the busy-exit scenario required by 1A-R8-02.

10. **Blocking — §2.7 action names; §3.2 README test.** Comparing the README with `ACTIONS` does not itself prove what the binary emits. `Vault::log` (`crates/akm-core/src/vault.rs:463`) accepts arbitrary strings, and committed names are constructed dynamically. The existing fake-child test (`crates/akm-cli/tests/security.rs:263`) checks the emitted name but does not compare it with the README. Extend the caller-level check to compare the actual fake child's journal action with the documented action, and preserve the existing journal strings and legacy-reader behavior.

11. **Advisory — §3.2 mask oracle.** "Prints no character of the secret" is not a valid general assertion for a constant mask. A one-character fake secret of `*` necessarily shares a character with `********`, even though the mask contains no secret-derived bytes. Assert the exact secret field and compare output across different secrets with otherwise identical metadata.

12. **Advisory — §4 limits; §5 final checks.** The plan does not identify the final-build real-surface evidence or its owner-gated limits. `docs/TESTING.md:66` calls for real Windows evidence for clipboard and session changes, while the protocol (`docs/design/unit1a-protocol.md:141`) requires checks bound to the final build hashes. Name the applicable checks, record any that cannot run under the owner gates as not checked, and retain R4-04 as deferred rather than implying work-unit completion.

13. **Advisory — §1.1 and §1.2 exit inventories.** `Open::drop` and `Win32::close` (`desktop/src-tauri/src/clipboard.rs:254`) ignore the `CloseClipboard` return, and the fake close cannot fail. A close failure is therefore outside the proposed outcomes and fault table. Either establish why it cannot occur for this open/thread lifetime or model and test the resulting uncertainty.
