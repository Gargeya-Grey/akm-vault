## Ranked findings

1. **P2: Dialog entry hides a focused control and its notice.** `desktop/src/styles.css:1656` fades the entire overlay and dialog from zero opacity. In headless Edge, I paused both animations at their first frame: focus was already in the import text field, while the dialog and its import-safety notice had opacity `0`. This contradicts the same-frame notice requirement. The capture is `dialog-first-frame.png` (review temporary folder). **Fix:** Keep dialog content and notices fully opaque from the first frame. Animate only a separate backdrop or remove the opacity animations.

2. **P2: The drain bar can say time is up while the secret remains visible.** `desktop/src/components/KeyDetail.tsx:243` starts an independent CSS animation, while the existing countdown uses `Date.now()`. With a simulated 40-second wall-clock rollback, the bar finished after 30 seconds while the fake secret remained visible and the text said "Hides in 39 seconds." The underlying clock sensitivity predates this diff; the misleading bar is new. **Fix:** Remove the bar or derive its displayed progress from the same remaining-time state as the text, resetting it on each reveal.

3. **P2: Reduced motion does not suppress the new press transforms.** The active-button selectors in `desktop/src/styles.css:500` are more specific than the reduced-motion overrides at line 1689. With reduced motion enabled, Edge still computed `scale(0.97)` for Add key. The new active row-arrow rule also moves the arrow 4 px. **Fix:** Put these transforms behind `prefers-reduced-motion: no-preference`, or use equally specific reduced-motion overrides for buttons and the row arrow.

4. **P3: Selected filters lose their hover-border feedback.** The `:has()` rule at `desktop/src/styles.css:523` overrides `select:hover`. In both themes, the selected Project filter kept its leaf border while hovered instead of switching to `--ink`. **Fix:** Lower the selected rule's specificity or add a more specific selected-filter hover rule inside the hover-capable media query.

5. **P3: Hover fills leave the house palette.** `desktop/src/styles.css:463` uses `color-mix()` for filled-button hover backgrounds, creating colours outside the specified tokens. The house style requires token colours and a forest fill for the primary button. **Fix:** Retain the token fill and use a token-based border, underline, or other hover cue.
