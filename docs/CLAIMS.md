# Claims

This page lists each promise that AKM makes to a user about security, privacy or data safety. Each row gives the claim in one sentence, the files that state it, the evidence and the limit. A claim that has no row here is not a promise. AKM is an untrusted development build: read [SECURITY.md](../SECURITY.md) first.

## How to read a row

- **Evidence** names a Rust test `fn` that exists, or a named proof from the list below. A test shows that the code behaves as stated in the test's setup. It does not show that an attacker fails.
- **Limit** says what the claim does not cover. Read it as part of the claim.
- `python tools/check_docs.py` fails when an evidence cell names a test that does not exist, a function that is not a test, or an unknown proof, when a proof does not resolve to things that exist and run (below), and when a row has no evidence or no limit. It reads Rust as code, so a test in a comment or a string does not count. `tools/test_check_docs.py` shows that the check fails on each of these mistakes.

## Named proofs

A proof name stands for a script or a workflow job. The check resolves each name (`PROOFS` in `tools/check_docs.py`): each of its files is tracked and present, a workflow proof's job is a key of the workflow's `jobs` mapping (not text in a comment or a scalar) and its `run` steps hold the proof's command, a frontend proof's title is a `test(` or `it(` call outside comments, and a Rust test that a job runs is a test fn. This table must list exactly those names, name each proof's file or job, and say "CI, each push" exactly for the proofs that the build workflow runs.

## Network, install and release

| Claim | Where stated | Evidence | Limit |
|---|---|---|---|
| AKM's own code has no network client and no listener. | README.md, docs/GETTING_STARTED.md, docs/THREAT_MODEL.md | `no-network-check` | The check looks for the usual entry points. It cannot prove that no connection exists. The WebView2 runtime is Microsoft software and is outside the claim. The setup program can download the runtime while it installs. |
| The setup program installs for the current Windows account only, without administrator approval. | docs/GETTING_STARTED.md, docs/FIRST_USE.md | `native-proof-install` | The job has never run, so no clean computer has proved this. The job checks that each install holds the `akm-desktop.exe` that its build hashed, with only the bundler's bundle-type mark (`tools/InstallBinding.psm1`). It also checks that a silent uninstall keeps the vault, the settings and the journal, but AKM does not promise that: docs/GETTING_STARTED.md tells the user to copy the vault first. The journal is in `%LOCALAPPDATA%\akm\journal`, inside the install folder `%LOCALAPPDATA%\AKM` (the same folder, because Windows ignores case). The uninstaller deletes the program files and the shortcuts, then removes the install folder only when it is empty, so the journal and its folder stay. Only the "Delete app data" box of an interactive uninstall removes more: `%APPDATA%\com.akm.desktop` (the settings) and `%LOCALAPPDATA%\com.akm.desktop` (the WebView2 data), with everything in them. The vault is wherever the user put it; a vault inside one of those two folders goes with them. These facts come from the template of tauri-bundler 2.10.4; a new bundler can change them, and the install job then fails. |
| THIRD_PARTY_NOTICES.md in the repository holds every licence, notice, copying, copyright and patent file that a shipped dependency ships, at any depth of its package, and CI fails when it is out of date. | README.md, CONTRIBUTING.md | `third-party-notices-check` | The texts come from each package's own files, or a standard text when a package ships none. The file can hold texts for code that AKM does not compile. The setup program and the app do not hold or show this file, so a release must attach it (docs/RELEASING.md). Nobody has given legal advice on it. |
| A public snapshot holds only files that are plain text (strict UTF-8 in NFC, with printable characters, tabs and LF or CR LF line ends only) or that the owner listed by SHA-256, and it refuses a path, an e-mail address or a name from this computer that its rules know, in a file's text or in a path. It never starts Git on the source repository, and it refuses a commit whose objects are not all in the source's own object store. | docs/TESTING.md, docs/RELEASING.md | `public-snapshot-scan` | The tool reads the source's Git folder as files and runs Git only on its own copy, which needs free disk space about the size of the source's object store. A repository in the reftable format, or with a repository extension that `tools/git_child.py` does not know, is refused. The scan is an aid, and the owner reads the tree before it becomes public. The rules are shapes, the exact `email <text>` entries of two lists and the private words that the owner lists; no line marker exists. The tool is not a secrets scanner: it does not decode base64, percent-encoding, HTML entities or escapes, or see an address split over two lines or written in words. An at sign is a character whose NFKC form holds U+0040, and a dot is one whose NFKC form holds U+002E or U+3002, in the Unicode version of the Python that runs the scan. It cannot read inside a file that is not UTF-8; the owner's check before listing it is the only check. It trusts the lists in the commit; CI's `generate_third_party_notices.py --check` keeps `notice-addresses.txt` equal to the generator's output. |
